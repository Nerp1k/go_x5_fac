## Что делает программа

Программа собирает сервис уведомлений из двух каналов: email и push. Каждый канал умеет хранить историю сообщений в памяти и возвращать ошибку, если сообщение пустое или канал не настроен. Диспетчер `Dispatch` рассылает сообщение по каналам и останавливается на первой ошибке, а `SafeDispatch` перехватывает панику одного канала, продолжает рассылку и возвращает все ошибки сразу.

## Как запустить

Все команды выполняются из папки `student` (модуль `lesson5/student`). Используется Go 1.22 или новее.

```bash
go run ./cmd/notify        # четыре случая из отчёта
go test -v ./practice      # тесты практики
go build ./...
go vet ./...
```

## Проверенные случаи

1. **Успешная рассылка.** Email с адресом и push с DeviceID, сообщение `Заказ готов` через `Dispatch`. Ошибки нет, истории обеих каналов содержат `[email] Заказ готов` и `[push] Заказ готов`.
2. **Пустой текст.** `Dispatch` с `""`. `errors.Is` распознаёт `ErrEmptyMessage` (`канал email: пустое сообщение`), истории каналов не меняются.
3. **Нет настройки.** Push без `DeviceID` и непустое сообщение. `errors.As` извлекает `*SendError`: канал `push`, причина `не задан device id`. История не меняется.
4. **Сломанный канал.** Сначала `BrokenNotifier`, затем исправный push в `SafeDispatch`. Возвращается ошибка с `ErrNotifierPanic` (`канал broken: паника канала: драйвер канала повреждён`), а следующий канал всё равно получил сообщение: история push содержит `[push] Заказ готов`.

## Обработка ошибок

`Dispatch` вызывает каналы по порядку и при первой же ошибке возвращает её, обёрнутую в контекст `канал <имя>: <причина>` через `%w`. Последующие каналы не вызываются. Причина и тип ошибки сохраняются, поэтому `errors.Is` находит sentinel (`ErrEmptyMessage`), а `errors.As` — `*SendError`.

`SafeDispatch` вызывает `SafeSend` для каждого канала, не останавливается на сбое и возвращает слайс всех ошибок в порядке каналов. Каждая ошибка тоже обёрнута контекстом канала. Разница в том, что обычный диспетчер прекращает рассылку после первой ошибки, а безопасный доставляет сообщение всем каналам и отдаёт полный список проблем.

`recover` находится внутри `SafeSend` вокруг отдельного вызова `Send`, а не вокруг цикла, потому что паника прерывает текущую горутину целиком. Если поместить `recover` снаружи цикла, паника первого канала остановит рассылку остальных. Обёрнутый вызов превращает панику в обычную ошибку, обёрнутую вокруг `ErrNotifierPanic`, и цикл спокойно переходит к следующему каналу.

`errors.Is` используется в `main` для распознавания `ErrEmptyMessage` и `ErrNotifierPanic`, а `errors.As` — для извлечения `*SendError` с полями `Channel` и `Reason`. Это надёжнее сравнения текста ошибки: обёртки через `%w` сохраняют цепочку причин.
